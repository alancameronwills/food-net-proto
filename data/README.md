# Role-play organisations

`organisations.json` is the list of fictional buyers, producers and the operator shown in the role picker.
Edit it in any text editor, then run:

    npm run check:data      # validates the file and says exactly what is wrong
    npm run reset           # reloads it into the local demo session (restart the API if it is running)

Each entry:

| field | notes |
|---|---|
| `id` | unique; lowercase letters, digits, hyphens. Used in role links (`?as=<id>`) |
| `role` | `buyer`, `producer` or `operator` (exactly one operator) |
| `name`, `kind`, `town` | shown on cards. `kind` e.g. restaurant, hotel, retailer, caterer, farm, fisher, butcher, baker, dairy, packer |
| `lat`, `lon` | location; drive distances to everyone else are calculated from these (straight line x 1.35) |
| `blurb` | `{ "en": "...", "cy": "..." }`; `cy` is optional and falls back to English |
| `certifications` | producers only, optional, e.g. `["organic"]` |
| `offers` | producers only: `{ "product": "<product id>", "price": 1.50, "minOrder": 5 }`; optionally `"shelfLifeDays": 5` (how long it keeps after delivery; otherwise the usual for the product type: milk, bread and fish 2 days, meat 5, vegetables 7, eggs 14, cheese 60). Producers can also change this in the app |

Product ids you can offer: milk-whole, milk-semi, cream-double, eggs-free, bread-sour, bara-brith, veg-leek,
veg-potato, veg-carrot, veg-tomato, veg-kale, meat-lamb, meat-beef, meat-sausage, fish-crab, fish-lobster,
fish-bass, fish-mackerel, cheese-cheddar, cheese-blue. (Products live in `src/server/seed.ts`.)

Personas appear in the app after the session is reset; the operator's "Reset demo data" button also reloads the file
(on a deployed copy, after redeploying).

## Producer stock (Phase 2)

Seed supply windows are generated by `npm run reset` (this week and the next five, running from in stock to forecast to
provisional). Producers then manage their own stock in the app: **Stock & forecast** (weekly quantity and confidence,
"Add next 4 weeks") and **My listings** (products, price, minimum order, volume prices when that pricing model is on).

## Trust information (Phase 4)

Producers can also have:

| field | notes |
|---|---|
| `verified` | `true` shows a "Verified member" badge under the *Verified badges* trust model |
| `baseline` | `{ "orders": 40, "fillRate": 0.95 }`: the producer's past delivery record. The reliability score blends this with deliveries recorded in the demo |

## Delivery areas and rounds (Phase 6)

`areas.json` lists the delivery areas (id, name in English and Welsh, a centre point). Every organisation belongs to the
area nearest to its location, so moving a business in `organisations.json` moves it between areas automatically.

Under the *Area delivery days* model a producer's `routes` say which weekdays they deliver to each area:

    "routes": { "teifi": [1, 4], "fishguard": [2, 5] }     // 0 = Sunday ... 6 = Saturday

A producer with no `routes` at all delivers on the product's usual days everywhere; a producer with `routes` but none for
an area does not deliver there. Under the *Hub courier* model the operator sets the hub days in the Model Lab instead.
